GaussianBench

Physics-fidelity evaluation for Gaussian scene representations

Chukwudalu Dumebi-KachikwuSTAR Labs, University of Maryland

Paper arXiv Code BibTeX

Can a system do more than make physics look right?

3D Gaussian Splatting is moving from static reconstruction toward systems meant to predict how scenes change under interaction. Those systems are usually judged by rendered motion or a method-specific task, yet a rollout can look plausible while conserving momentum incorrectly, transmitting force wrongly across a material boundary, or never reaching the deformation it was asked for. GaussianBench tests those claims directly, from exported physical state.

  1. 1Lock the test

    Before any system is tested, each scene is fixed in advance: the setup, the correct answer, the conditions where the test applies, and how much error is allowed.

  2. 2Run the system

    Each published system runs the same scene with its own, unmodified physics code, and we record what it actually does.

  3. 3Grade the result

    Automated checks compare the result with the correct answer, give a verdict, and point to exactly which part of the physics went wrong.

Pass
The system got the right answer, within the allowed error.
Fail
The system ran the test and got the wrong answer: a real physics mistake.
Invalid
The system never reached the situation the test asks for, so the result can’t be judged.
NA
The system can’t do what this test needs, so the test is skipped.

Test the motion, the relationships, and the representation.

Each protocol asks a different question of the same exported state, so a failure can be attributed to wrong motion, wrong constitutive response, wrong Gaussian-state transport, or an invalid regime.

ADynamics

Does the object obey basic physics over time?

Does a dropped, struck or vibrating object move the way textbook physics says it should? We check momentum conservation, beam frequency, stress-wave speed, Poisson contraction, melt-front motion and free fall, each against a known solution.

A1 conservation · A2 Euler–Bernoulli · A3 wave speed · A4 Neumann–Stefan · A5 Poisson · A6 free fall

BRelationships

Does it preserve relationships and respond to change?

Real objects are often made of more than one material, and a good simulator should react sensibly when conditions change. A bimaterial bar checks regional strains and the force passed across the boundary (interface traction). Interventions change one input (gravity, temperature, or material assignment) and compare against the predicted counterfactual, so a system can’t pass by replaying a memorized motion.

B1 series bar · thermal intervention · material repainting

CGaussian state

Does the representation itself stay physically correct?

Each Gaussian is a small blob whose shape (its covariance) should stretch and turn with the material around it. A position-fitted deformation checks whether the requested motion happened; Σ′=FΣ0F⊤ checks whether each blob’s shape followed it. Health, rendering and native-triangle checks complete the tier.

C1 affine · C2 shear and health · C3 render · C4 captured beam · C5–C8 triangle state

MMeasured material

Does the constitutive law match real material?

Matching a textbook formula isn’t the same as matching a real material, so we compare against lab measurements of stretched rubber. Simulated stress–strain is compared with an independent three-term Yeoh fit to ASTM D412 natural-rubber measurements, up to 150% engineering strain.

M1 ASTM D412

Every scene, every system

105% error

Getting one material right doesn’t mean getting two right.

OmniPhysGS and PhysDreamer pass the single-material tests (beam, wave and Poisson). But join two different materials into one bar (B1) and their stretch is off by up to 105.0% and 105.6%, and the forces on either side of the joint disagree by 55%.

45.3% vs 0.075%

An object can move wrong even when its Gaussians follow correctly.

Asked to shear an object, PhysGaussian and Physics3D get only partway there, missing the requested shape by 45.3%, so the test is INVALID. Yet each Gaussian’s shape follows the motion that did happen almost exactly, to within 0.075%. The benchmark tells these two problems apart.

Verdicts that hold when the rules move.

How much error a test allows is a judgment call, so we checked whether our conclusions depend on it. Every result is re-graded with the allowed error anywhere from half to double, using the same saved outputs without rerunning any simulation. Drag the slider to see which verdicts change.

GaussianFlesh runs every test.

Our reference system treats each Gaussian as both something you see and a piece of physical material. One shared solver (UL-MLS-MPM) lets a single object mix stiff, soft and plastic parts that push on each other naturally.

That design lets it handle:

  • Shape that tracks motion. Each Gaussian stretches and turns with the material around it (Σp=FpΣ0,pFp⊤).
  • Many materials. Rubber, metal, clay, and material that melts.
  • Heat. Temperature spreads through an object, softens it, and can melt it.

It passes 11 of its 12 tests, missing only the strictest momentum check (A1a). It shows one way to meet the benchmark; the benchmark itself is the contribution.

Visual plausibility is not physical correctness.

As Gaussian splatting moves toward interactive scenes and world models, believable pixels are not enough. GaussianBench makes behavior under new forces, contacts, materials and temperatures measurable, attributable and reproducible, and tells us which part failed.
